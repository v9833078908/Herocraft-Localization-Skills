# Hero Craft Localization Skills

**Три навыка для агента, которые превращают выгрузку строк из игры в готовый
проект локализации: кит, глоссарий и промпты движка автоподсказок.**

Русский · [English](README.en.md)

Скиллы работают в любом агенте, поддерживающем открытый стандарт
[Agent Skills](https://agentskills.io/specification): Claude Code, Codex CLI,
Cursor, OpenCode, Gemini CLI, GitHub Copilot CLI, Amp, Zed, omp. Один и тот же
`SKILL.md`, разные каталоги установки - этим занимается `install.sh`.

## Установка

```sh
git clone https://github.com/v9833078908/Herocraft-Localization-Skills.git
cd Herocraft-Localization-Skills
./install.sh
```

> [!IMPORTANT]
> **Перезапустите агента после установки.** Почти все агенты читают список
> скиллов один раз, при старте сессии. В уже открытой сессии новые файлы
> лежат на диске невидимо: скилл не предложится и по имени не вызовется.
> То же касается обновления: `git pull` без перезапуска ничего не меняет.

`./install.sh --list` покажет, какие агенты найдены на машине, `--dry-run` -
план без изменений, `--copy` - копии вместо символических ссылок (Windows),
`--project ~/путь` - установка внутрь одного проекта, `--uninstall` - удаление.

Проверить, что агент увидел скиллы: `/skills list` (Claude Code, Copilot CLI,
Gemini CLI), `/skills` (Codex CLI), **Customize → Skills** (Cursor), в omp -
просто спросить, какие скиллы доступны.

## Что внутри

| Шаг | Скилл | Что делает | Когда звать |
|---|---|---|---|
| 1 | [`preparing-weblate-loc-kits`](skills/preparing-weblate-loc-kits/SKILL.md) | Превращает выгрузку CSV/TSV/XLSX/TXT в файл, который принимает интерфейс создания компонента, не теряя языков и не выдумывая ключи | «Пришёл кит от разработчика, надо загрузить в Weblate» |
| 2 | [`game-glossary-builder`](skills/game-glossary-builder/SKILL.md) | Собирает глоссарий по тому же киту: термины, переводы, пояснения, отдельно - флаги-исключения | «Нужен глоссарий для нового проекта» |
| 3 | [`weblate-machinery-prompts`](skills/weblate-machinery-prompts/SKILL.md) | Пишет `persona`, `style` и `language_instructions` для `/machinery/<проект>/<движок>/` по доказательствам из кита и глоссария | «Настроить промпты автоподсказок и судьи» |

Порядок важен: каждый следующий шаг опирается на артефакт предыдущего.
Подробно - [docs/workflow.md](docs/workflow.md).

## Как скиллы себя ведут

- **Исходный язык по умолчанию русский.** Киты Hero Craft пишутся на русском,
  поэтому скиллы не выясняют язык источника заново: они просят подтвердить
  `ru` и фиксируют допущение в отчёте. Другой язык - только по прямому
  указанию или когда сам кит противоречит допущению; выводить язык из порядка
  колонок запрещено, потому что в Weblate он неизменяем.
- **Спрашивают, а не угадывают.** Каждый начинает с короткого интервью на
  русском: смысл колонок, регистр, политика мата, состояние глоссария. Нет
  ответа - нет догадки.
- **Говорят по-русски, пишут по контракту.** Общение и отчёты - на русском;
  заголовки CSV, коды языков и токены флагов остаются машинными.
- **Ничего не деплоят.** Работают с файлами, не опрашивают живой Weblate, не
  переводят пустые ячейки, не покупают вызовы модели. Результат - файл или
  текст, который человек проверяет и применяет сам.
- **Проверяют результат.** Кит считается готовым только после прогона
  `loc_kit_ingest`, промпты - после прогона формы и промпта в dev-контейнере.

## Совместимость

`install.sh` использует три каталога, и этого хватает восьми агентам:

| Каталог | Кто читает |
|---|---|
| `~/.agents/skills/` | Codex CLI, Cursor, OpenCode, Amp, Zed, Copilot CLI, omp |
| `~/.claude/skills/` | Claude Code |
| `~/.gemini/skills/` | Gemini CLI |

Полная таблица путей, ограничений и ссылок на документацию каждого агента -
[docs/compatibility.md](docs/compatibility.md).

## Обновление

```sh
cd Herocraft-Localization-Skills && git pull && ./install.sh
```

При установке ссылками (по умолчанию) `git pull` уже обновил файлы, повторный
`install.sh` нужен только чтобы добавить новые скиллы. При `--copy` запускать
установку после каждого `git pull` обязательно.

## Попробовать без своих данных

В [examples/demo-kit](examples/demo-kit) лежит выдуманный кит небольшой игры и
его глоссарий. На них можно пройти все три шага, не открывая рабочие файлы.

## Что это не решает

Скиллы написаны под контракты HCGameLoc - форка Weblate для Hero Craft
(`l10n.herocraft.com`): свои проверки игровой разметки, свои движки
автоподсказок, свой LLM-судья. В стандартном Weblate часть путей и проверок
не совпадёт. Скиллы не переводят строки за переводчика, не решают за продюсера
и не заменяют LQA.

## Проверка и вклад

```sh
python3 tools/validate_skills.py     # frontmatter, имена, длины, вложенность, ссылки
```

Эта же проверка запускается в CI на каждый push и pull request. Как предложить
правку формулировки, даже не работая с git - [CONTRIBUTING.md](CONTRIBUTING.md).
Нашли, что скилл ведёт себя неправильно - откройте
[issue](https://github.com/v9833078908/Herocraft-Localization-Skills/issues/new/choose).

## Доверие и безопасность

Скилл - это инструкции, которые ваш агент исполняет. Устанавливайте скиллы
только из источников, которым доверяете, и читайте `SKILL.md` перед
установкой: здесь всего три файла, каждый обозримого размера. Ни один скилл в
этом репозитории не обращается к внешним сетевым источникам и не просит
предварительного разрешения на выполнение команд.
